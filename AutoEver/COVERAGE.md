## 학습 순서와 분량 조정

1. 지난 시험 대비: 이중우선순위큐 → CSES 두 힙 변형 → 일반 섬 연결하기 → 필수 연결 MST 변형.
2. 빠진 범위 채우기: 성적 평균 → 주차 요금 계산 → 보석 쇼핑 → 1차원 차분배열 몸풀기 → 파괴되지 않은 건물(3차 점검에서 여유로 강등, 시간이 남을 때만).
3. DP·그리디 보완: 정수 삼각형 → [등굣길](./2026-10-22_DP_그리디/2_여유_등굣길/Main.java)(정수 삼각형 다음 우선 보완) → 징검다리 → 강의실 배정. Java 배낭 경험이 없으면 기존 [Knapsack 1](https://atcoder.jp/contests/dp/tasks/dp_d) / [연습 파일](./2026-10-22_DP_그리디/2_여유_EDPC_D_Knapsack1/Main.java)을 진행한다(새 배낭 문제를 찾지 않는다).
4. 구현 보완: 기존 [프렌즈4블록](https://school.programmers.co.kr/learn/courses/30/lessons/17679) / [연습 파일](./2026-10-14_구현_해시맵_스택큐덱/1_필수_프렌즈4블록/Main.java)을 **필수로 승격**.
5. 힙 보완: 기존 [디스크 컨트롤러](https://school.programmers.co.kr/learn/courses/30/lessons/42627) / [연습 파일](./2026-10-18_힙_이중우선순위큐/1_필수_디스크컨트롤러/Main.java)을 **필수로 승격**. 선택으로 [Process Tasks Using Servers](./2026-10-18_힙_이중우선순위큐/3_선택_ProcessTasksUsingServers/README.md)를 추가했다.

하루 3시간에 신규 필수와 기존 필수를 전부 몰아 풀지 않는다. 이미 해결한 쉬운 문제는 복습만 하고, 그 시간을 빠진 유형에 사용한다. 도둑질은 원형 배열 DP이며 배낭이 아니므로 학습 우선순위를 여유로 낮췄다. 기존 도둑질 연습 폴더 이름은 유지했다.

## 지난 시험 설명의 불확실성

- "힙 2번"만으로 이중우선순위큐라고 확정할 수 없다. 이중우선순위큐는 최소/최대 동기화, 자원 배정은 종료 시간/자원 번호 관리로 역할이 다르다.
- CSES 원문은 아무 유효한 방 번호나 허용하고 힙 1개로도 풀 수 있다. 연습에서는 "빈 방 중 가장 작은 번호 우선"을 추가해 두 힙을 모두 사용한다. 추가 조건을 원문 요구로 오해하지 않는다.
- MST 자체 변형은 무료 사전 연결과 유료 필수 간선을 각각 다룬다. 유료 필수 간선에 사이클이 있고 이를 허용하면 최종 결과는 엄밀한 의미의 트리가 아니라 최소 비용 연결 그래프다.
- 특정 노드를 반드시 방문하는 최단 경로가 실제 조건이라면 MST가 아닌 최단 경로 문제다.

## 링크 확인 기록

2026-10-16에 위 프로그래머스 원본 페이지와 NGV 3개 문제의 공개 설명·예제를 확인했다. [NGV 알고리즘 목록](https://exam.hyundai-ngv.com/practice?type=ALGORITHM)의 공개 목록 11페이지를 확인해 보완 문제를 선정했다. CSES 원문·예제도 확인했다.

백준 12764는 이번 확인에서 문제 대신 서비스 안내 페이지가 나와 필수 목록에 넣지 않았다. 프로그래머스·NGV에서 이번 두 힙 연습 조건과 직접 일치하는 문제를 확보하지 못해 CSES를 선택했다. 필수 연결 MST는 원본 링크가 있는 자체 변형이며 별도 온라인 judge는 없다.

이번 보완은 문제 범위 점검이다. Main.java 연습 틀의 TODO는 사용자가 직접 구현해야 하며, 기존 풀이 전체의 정답 여부를 검증한 것은 아니다.

생성 후 검증: Java 연습 틀 8개를 각각 독립된 임시 출력 폴더로 컴파일했고 모두 통과했다. 보완 목록·문제 README·관련 날짜 계획 등 문서 17개의 로컬 링크도 확인했다. 연습용 TODO가 남아 있으므로 알고리즘 정답 검증은 사용자가 구현한 뒤 진행한다.
