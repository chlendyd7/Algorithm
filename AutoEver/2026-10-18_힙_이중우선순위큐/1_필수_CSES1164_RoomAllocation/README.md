# Room Allocation — 두 힙 자원 배정 연습

- 원문: [CSES 1164](https://cses.fi/problemset/task/1164/)
- 우선순위: 필수. 최소/최대 동기화와 다른 두 힙 패턴을 보완.
- 연습 파일: [Main.java](./Main.java). allocateRooms를 구현.
- 선정 이유: 프로그래머스·NGV 목록에서 이 연습 조건과 직접 일치하는 문제를 확보하지 못했다. 백준 12764는 2026-10-16 확인 시 서비스 안내 페이지로 연결됐다. CSES 원문과 예제는 공개 페이지에서 확인했다.

## 원문과 연습 추가 조건

원문: 모든 손님에게 방을 배정하고 사용하는 방 수를 최소화한다. 유효한 방 번호 배정은 아무 것이나 허용된다.

연습 추가 조건: 재사용 가능한 방이 여러 개면 가장 작은 번호를 선택한다. 입실일이 같은 손님은 입력 순서대로 처리한다. 이는 원문 요구가 아니라 두 힙을 연습하기 위한 조건이며, 이 조건으로 만든 답도 CSES에 제출할 수 있다.

- 사용 중인 방: 퇴실일 기준 최소 힙.
- 빈 방: 방 번호 기준 최소 힙.
- 손님: 입실일 순으로 정렬하되 원래 인덱스를 보관.

원문 자체는 힙 1개로도 풀 수 있다. 이중우선순위큐처럼 같은 원소를 최소/최대 힙에 복제하는 문제가 아니라, 자원이 사용 중/빈 상태 사이에서 이동하는 문제다.

## 원문 예제

입력:

```text
3
1 2
2 4
4 4
```

출력 가능한 정답:

```text
2
1 2 1
```

## 확인할 조건

- **퇴실일 < 입실일**이어야 재사용. 같은 날은 재사용 불가. NGV 강의실 배정의 경계 조건과 다르다.
- 새 손님이 올 때 재사용 가능한 방을 전부 빈 방 힙으로 옮긴 뒤 최소 번호를 선택.
- 최종 출력은 정렬된 순서가 아니라 원래 입력 순서.
- N≤200,000, 날짜≤1,000,000,000. 목표 O(N log N).
- 자체 예제: [1,2], [1,3], [4,4] → 방 수 2, 배정 [1,2,1]. 방 여러 개가 동시에 재사용 가능해지는 경우를 확인.
- 자기 예제: [1,1], [1,1] → 방 수 2, 배정 [1,2].
