1. 구현 난이도가 가장 높았던 프로젝트 (약 620자)

Click-CEO 프로젝트에서 실시간 호가창 매칭 시스템을 구현할 때 난이도가 가장 높았습니다. 대용량 트래픽을 재현하기 위해 봇 주문을 대량 생성했는데, 기존 팀원이 구현한 polling 방식은 실시간성이 떨어진다고 판단해 WebSocket으로 전환했습니다. 그런데 부하 테스트 결과 연결 실패율이 44%에 달했습니다. 원인을 분석해보니 봇들이 1초 간격에 동시에 주문을 쏟아내며 초당 스파이크 트래픽이 발생했고, 이 주문을 매칭·정산하는 무거운 트랜잭션 처리가 WebSocket 연결을 수용하는 서버 자원까지 함께 점유해 신규 연결 handshake가 타임아웃되는 구조적 문제였습니다. 이를 해결하기 위해 주문 매칭 로직을 Kafka 메시지 큐를 통해 별도 컨슈머 서버로 분리해 무거운 트랜잭션 부하를 WebSocket 서버에서 격리했습니다. 또한 봇 주문 생성 타이밍도 1초 단위로 동시에 몰리던 구조에서 ms 단위로 분산시켜 스트림처럼 흘려보내고, 이렇게 분산된 요청을 다시 배치로 묶어 처리해 처리 효율까지 확보했습니다. 그 결과 WebSocket 연결 실패율을 44%에서 0%로 개선했고, 실시간성과 안정성을 동시에 확보한 시스템을 구현할 수 있었습니다.

2. 가장 효과적으로 트러블슈팅한 사례 (약 590자)

현대위아 MES 시스템에서 모의해킹 진단 결과 URL 레벨 권한 검증이 없다는 취약점이 발견됐습니다. 기존에는 권한 없는 메뉴를 화면에서 숨기는 방식으로만 통제하고 있어, 사용자가 URL을 직접 호출하면 UI 통제를 우회해 접근할 수 있는 구조적 문제였습니다. Spring Security 등 인증 프레임워크를 새로 도입하는 방법도 고려했지만, 기존 시스템과의 호환성과 일정을 고려해 기존 권한 체계를 확장하는 방향으로 풀기로 판단했습니다. 기존 role 체계에 CRUD 권한 개념을 결합해 url-role-user 매핑 테이블을 설계하고, 인터셉터가 매 요청마다 세션의 user와 role 정보만 확인하도록 구현했습니다. url-role 매핑 정보는 서버 기동 시 인메모리에 캐싱해 두어, 매 요청마다 DB를 조회하는 대신 O(1) 해시 조회로 대체함으로써 DB round trip에 따른 지연을 제거했습니다. 새로운 인증 체계를 처음부터 구축하지 않고 기존 기능과 통합하는 방식으로 접근한 덕분에, 짧은 기간 안에 URL 단위 접근 통제를 적용해 취약점을 해소할 수 있었습니다.
